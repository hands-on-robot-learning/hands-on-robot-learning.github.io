## What you will learn

- How to design a demo that is both compelling and honest
- How to control variables (cameras, resets, evaluation protocol) in an end-to-end system
- How generalist policies fail, and how to characterize those failures

## Required hardware/software

- SO-101 follower arm
- Camera note: fixed external camera is the minimum fallback; fixed + wrist is preferred for SmolVLA-style workflows.
- VLA / SmolVLA-style model tooling. The exact workflow will be finalized as the course stack stabilizes.

## Possible tracks

- Base-model deployment
- Small-data finetuning or adaptation
- VLA vs. task-specific policy comparison
- New manipulation task
- Camera or sensor ablation

## Evaluation protocol

- Use a clearly defined task, reset procedure, and evaluation protocol.
- Record continuous video for evaluation runs, and distinguish practice vs evaluation.
- Report both successes and failures, and describe any deviations.

## Common failure modes

<aside className="hol-assignment-callout hol-assignment-callout--failure">
	<h3>Common failure modes</h3>
	<ul>
		<li>Ambiguous instructions leading to inconsistent behavior</li>
		<li>Camera distribution shift (mount, lighting, viewpoint) causing brittle execution</li>
		<li>Latency/control-frequency mismatch causing delayed or oscillatory actions</li>
		<li>“Demo-only” success that disappears under repeatable evaluation</li>
	</ul>
</aside>

## How to get unstuck

<aside className="hol-assignment-callout hol-assignment-callout--tip">
	<h3>Debugging tips</h3>
	<ul>
		<li>Simplify the task until the system is repeatable, then add complexity back.</li>
		<li>Use ablations: remove language, remove wrist camera, reduce observation set, etc.</li>
		<li>Compare against your A3 system and keep the evaluation protocol consistent.</li>
	</ul>
</aside>
