There are **no exams**. All students complete the same **four assignments** in this first offering.

## Breakdown

| Component | Weight |
| --- | ---: |
| Assignment 1: Build, Calibrate, and Teleoperate the SO-101 | 15% |
| Assignment 2: Handcrafted Cube-Picking Baseline | 20% |
| Assignment 3: LeRobot Imitation-Learning Challenge | 30% |
| Assignment 4: VLA / SmolVLA Deployment and Final Demo | 25% |
| Participation, paper lightning talk, peer evaluation, and engineering citizenship | 10% |

## Grading philosophy

- The course grades **engineering process**, **reproducibility**, and **honest evaluation**.
- A team can earn a strong grade even if its robot does not achieve the best success rate.

## Leaderboards

Leaderboards are used as motivation and feedback. They help us iterate quickly and learn what breaks.

They are **not** gatekeeping: strong grades come from clear evidence, fair evaluation, and solid engineering.

## What earns a strong grade?

- Safe, careful operation and good hardware hygiene
- Reproducible setups (configs, scripts, versions)
- Evaluation discipline (defined trials, clear metrics, honest reporting)
- Clear debugging writeups and failure analysis (with videos)
- Clean, readable code and documentation that another team could run

## What loses credit?

- Unsafe robot operation or ignoring safety guidance
- Results without evidence (no videos, no reproducible config/command, unclear protocol)
- Cherry-picking: showing only successes without acknowledging failures
- Unexplained discrepancies between what was run and what is reported
- Missing contribution statements / peer-evaluation requirements when requested
